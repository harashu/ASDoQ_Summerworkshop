# 知識ベース

オーケストレーターだけが読む知識です。ペルソナには渡しません。

## ファイル

| ファイル | ID接頭辞 | 内容 |
|---|---|---|
| `company_template.md` | `K-TPL-` | 社内テンプレートの必須章・記述ルール |
| `domain_knowhow.md` | `K-DOM-` | 業界の規格・過去のトラブル事例・慣習 |
| `customer_profile.md` | `K-CUS-` | 顧客の特性・重視点・過去の指摘傾向 |

## 書き方のルール

オーケストレーターが引用して補正の根拠にするため、次の形式で書いてください。

```markdown
### K-TPL-01 要求仕様書には非機能要求の章を設ける
- 対象文書：要求仕様書
- 関連する副特性：目的明示性
- 強さ：必須 ／ 推奨 ／ 参考
- 内容：（1〜3文）
```

- **1項目に1つのルール**にしてください。
- **強さ**は補正の大きさの目安です。必須なら大きく、参考なら小さく補正します。
- IDは一度付けたら変えないでください（判断の記録から参照されるため）。

各ファイルの中身は例です。実際の会社・業界・顧客の情報に書き換えてください。
