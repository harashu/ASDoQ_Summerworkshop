# レビュアーペルソナ プロンプト集

ASDoQ文書品質モデルに基づくマルチペルソナ文書レビューエージェント用のプロンプトです。

全体の設計（ワークフロー・スコア計算・評価計画）は [docs/design.md](../docs/design.md) を参照してください。

## 構成

```
prompts/
├── README.md                  … このファイル
├── common/
│   └── reviewer_base.md       … 全ペルソナ共通のシステムプロンプト（ASDoQ特性・ルール・出力形式）
├── orchestrator/
│   ├── 01_panel_selection.md  … パネル選定（文書種別が標準パネル表にない場合だけ使う）
│   └── 02_integration.md      … 統合・最終レビュー作成
└── personas/
    ├── A01〜A11_*.md          … A 立場型（誰として読むか）
    ├── B01〜B09_*.md          … B 思考スタイル型（どう考えるか）
    └── C01〜C09_*.md          … C 困った人型（どう伝えるか）
```

## ペルソナファイルの構造

各ペルソナファイルは **フロントマター（オーケストレーター用）** と **本文（ペルソナ用）** に分かれています。

| 部分 | 渡す相手 | 内容 |
|---|---|---|
| フロントマター（`---` で囲まれた部分） | オーケストレーターのみ | 重点特性の重み `focus`、基礎信頼度 `base_reliability`、隠れた価値 `hidden_value`、補正方針 `orchestrator_hint` |
| 本文 | ペルソナ | 人物像、口調、観点、盲点 |

> フロントマターはペルソナに渡さないでください。「あなたの指摘は割り引かれる」などの情報を知ると、ペルソナが役を演じ切れなくなります。

## 組み立て方

```
[system]  common/reviewer_base.md  +  personas/XXX.md の本文
[user]    レビュー対象の文書  +  文書種別・目的・想定読者（わかる範囲で）
```

- 会社テンプレ・業界ノウハウ・顧客特性などの知識は **オーケストレーターだけが持ちます**。ペルソナには渡しません。
- ただし `A06` や `C06` のように、担当領域などの補足情報を受け取れるペルソナもあります（各本文に記載）。

## フロントマターの項目

| 項目 | 意味 |
|---|---|
| `focus` | 6特性ごとの重点度（合計1.0）。どの特性の指摘を信頼するかの初期値 |
| `sub_focus` | 主に見る品質副特性の一覧 |
| `base_reliability` | 指摘の基礎信頼度（0〜1）。性格によるノイズの大きさを表す |
| `severity_bias` | 重要度のつけ方の偏り。例：`-1.5` は実際より控えめにつけがちなので、+1.5 補正する |
| `hidden_value` | 性格の裏にある、そのペルソナならではの価値 |
| `orchestrator_hint` | オーケストレーターが指摘を扱うときの方針 |

## ASDoQ文書品質モデルとの対応

- `common/reviewer_base.md` には、**ASDoQシステム開発文書品質モデル Ver. 2.0a** の6品質特性・17品質副特性・測定項目と、「再構成版用解説」にある紛らわしい副特性の見分け方を載せています。
- 各ペルソナの「レビューの観点」には、対応する副特性を【】で付けています。フロントマターの `sub_focus` は、そのペルソナが主に見る副特性の一覧です。
- 測定基準と記述例（適合例／非適合例）は、解説資料の時点でレビュー中のため載せていません。確定したら `reviewer_base.md` に追加してください。
